Validated source commit: `492805b07ad23feb6b9eb817905754863a759018`

This commit intentionally remains the last source baseline on which the matrix
below was exercised. Later feature commits are not retroactively claimed as
part of this matrix; later documentation-only commits do not change the
compatibility evidence, and no untested environment is promoted to `PASS`.

## Protocol behavior

- Extension 1.8.0 requires authenticated service metadata before collection.
- A healthy 1.7.4 service without `/api/meta` is reported as incompatible instead of disconnected.
- Unsupported `page_variant` values are not silently removed and retried.
- Service 1.8.0 reports API protocol 1 and `.pagenest` format 1.
- Local HTML adds optional source fields without increasing the protocol number.
- The server-side downloader remains HTTP(S)-only; `file://` is rejected.

## Upgrade coverage

The real v1.7.4 installer was installed into an isolated directory and used to create a historical page. The real v1.8.0 installer then performed the normal overwrite upgrade while the 1.7.4 service was running. The Vault, page hashes, token, port and one Startup entry were preserved; only one isolated service instance remained. Post-upgrade HTTP and local HTML saves and duplicate detection passed.
